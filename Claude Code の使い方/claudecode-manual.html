基本操作

起動方法

# プロジェクトフォルダで起動
cd your-project
claude

# 最後のセッションを再開
claude --continue

# セッション選択して再開
claude --resume

非対話モード（スクリプト用）

# テキスト出力
claude -p "ファイルを要約して"

# JSON出力
claude -p "API一覧をJSON形式で" \
  --output-format json

# ストリーミング
claude -p "ログを分析" \
  --output-format stream-json

権限モード

# 自動判定モード
claude --permission-mode auto -p "lintを修正"

# 編集のみ自動許可
claude --permission-mode acceptEdits

Shift+Tab でセッション中に切り替え可能

画像を含む指示

スクリーンショットから直接HTMLを作成できる

# Windowsの場合
Alt+V  # クリップボード画像を貼り付け

"このデザインをHTMLで実装して"

このプロジェクトで使えるスキル（カスタムコマンド）

/init プロジェクト

CLAUDE.mdを自動生成。新規プロジェクトで最初に実行する。

/review コード

PR or 現在のブランチをレビュー。変更点の品質確認に使う。

/simplify 品質

変更済みコードを品質・効率・再利用性の観点でレビュー＆修正。

CLAUDE.md — 永続的な指示書

💡
CLAUDE.mdはセッション開始時に毎回読み込まれる。Claudeへの「お願い書き」。

配置場所と優先度

場所対象範囲Git管理
~/.claude/CLAUDE.md全プロジェクト共通不要
./CLAUDE.mdこのプロジェクト全員あり
./CLAUDE.local.md自分だけ.gitignoreへ
.claude/rules/ファイルパス別ルールあり

書くべき内容 / 書かない内容

書くべき内容 ✓

  • ビルド・テストコマンド
  • コード規約（インデント・命名規則）
  • アーキテクチャの決定事項
  • よくあるミス・注意点
  • NGな表現・禁止事項
  • 文体・トーンの指示

書かない内容 ✗

  • コードを読めばわかる情報
  • APIドキュメント全文
  • 頻繁に変わる情報
  • 長い説明・チュートリアル
  • 200行以上の冗長な指示

確認コマンド

/memory   # CLAUDE.md・自動記憶の一覧確認・編集

MCP サーバー — 外部ツール連携

MCPサーバーは外部ツール・サービスをClaudeに接続するプロトコル。GitHub・データベース・Slack・Canvaなどと直接連携できる。

追加方法（CLIコマンド）

# HTTP型（APIサービス）
claude mcp add --transport http サーバー名 URL \
  --header "Authorization: Bearer TOKEN"

# stdio型（ローカルツール）
claude mcp add --transport stdio サーバー名 コマンド

設定ファイルで追加（.claude/.mcp.json）

{
  "mcpServers": {
    "github": {
      "transport": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer YOUR_TOKEN" }
    }
  }
}

主なMCPサーバー一覧

サーバー機能用途
GitHubIssue・PR操作GitHub自動化
Canvaデザイン読み取り・生成デザイン作業
Google Calendar予定確認・追加スケジュール管理
Playwrightブラウザ自動化スクレイピング・テスト
Slackメッセージ送受信Slack連携
NotionDB読み書きNotion同期
Gmailメール操作メール自動化
 
/mcp   # セッション内でMCP状態を確認・再接続

Hooks — 自動化トリガー

特定のイベント発生時に自動でシェルコマンドを実行する仕組み。
「自動化したい動作」はメモリではなくHooksで設定する。

⚠️
「作業後に毎回〇〇して」という指示はHooksで設定しないと確実に実行されない。設定は .claude/settings.json に書く。

主要なイベント

イベント実行タイミング用途例
SessionStartセッション開始時環境変数設定・初期化
UserPromptSubmitユーザー入力後入力の前処理
PreToolUseツール実行前事前確認・ログ
PostToolUseツール実行後自動lint・フォーマット
Stopセッション終了時ログ保存・クリーンアップ

設定例：ファイル編集後に自動lint

{
  "hooks": {
    "PostToolUse": [
      {
        "if": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "eslint --fix {{file_path}}",
            "timeout": 10
          }
        ]
      }
    ]
  }
}

Settings — 設定ファイル

ファイルの場所と優先度

スコープ場所共有用途
User~/.claude/settings.json不要個人設定（全プロジェクト共通）
Project.claude/settings.jsonGit管理チーム共通設定
Local.claude/settings.local.json不要個人のプロジェクト設定

主要な設定項目

{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Read(./src/**)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)"
    ],
    "defaultMode": "acceptEdits"
  },
  "model": "claude-sonnet-4-6",
  "env": {
    "NODE_ENV": "development"
  }
}

Tips — 使いこなし術

コンテキスト管理

重くなったら圧縮。定期的に確認する習慣を。

/usage   # 使用量確認
/compact # 履歴圧縮
/clear   # リセット

効果的な指示の書き方

「何を」「どうしたい」「条件は何か」を明示する

❌ 悪い例
"このコードを改善して"

✅ 良い例
"@src/parse.ts のparse関数を改善して。
エッジケース：空文字・null・undefined。
テストが全パスすることを確認。"

ファイル参照

@-mention でファイルやディレクトリを直接参照

@src/components/Button.tsx
@src/components/  # フォルダ全体
@src/utils.ts#5-20  # 特定の行

並列処理

複数の独立した作業を同時に依頼できる

"以下を並列で実行してください：
1. src/auth/ のテストを書く
2. components/ のlintを修正
3. README.mdを更新"

計画モードの活用

大きな変更前に計画を確認する

Shift+Tab  # planモードに切り替え
"認証システムをリファクタリングして"
# → 実行前に計画を見せてくれる

デバッグの基本

エラーはそのまま貼り付ける

"以下のエラーが出ています：
[エラーメッセージをそのまま貼り付け]

@src/関連ファイル.ts を確認して原因と修正案を教えて"

合言葉・個人設定

新セッション開始時の合言葉

「ただいま」
直近の記憶・進行中の案件を呼び起こす
「AI会議」
AIチーム戦略モードに切り替え

メモリシステム

記憶は ~/.claude/projects/[プロジェクト名]/memory/ に保存される。

種別内容ファイル名例
user自分の情報・スキル・好みuser_role.md
feedbackやり方の修正・承認された判断feedback_style.md
project進行中の案件・決定事項project_current.md
reference外部システムへのポインタreference_repos.md
⚠️
「〜を覚えておいて」と言えばメモリに保存される。「〜を忘れて」で削除できる。
